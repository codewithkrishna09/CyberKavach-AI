Bypassing the Bots: Captcha Walls & Obfuscation

Phishers are weaponizing legitimate security tools to hide their tracks. By placing CAPTCHAs before fake login pages, they successfully block Google Safe Browsing bots from indexing their scams.

CyberKavach Threat Labs
Zero-Day Intelligence Team

1. The Death of the Blacklist

For the last decade, internet security relied on a simple concept: The Blacklist. When a scammer creates a fake banking website, global web crawlers (like Google Safe Browsing) scan it, detect the fake login form, and flag the domain. The next time a user opens it, Chrome blocks it with a giant red warning screen.

But what if the crawler bot can't see the login form? Hackers realized that if they can block the automated bots from reading the HTML, their domains will never get blacklisted. And ironically, they found the perfect tool to block bots: The CAPTCHA.

2. The CAPTCHA Shield

In modern zero-day phishing attacks, clicking a scam link no longer takes you directly to a fake SBI or HDFC page. Instead, it takes you to a completely legitimate-looking Cloudflare or reCAPTCHA verification page.

When Google's security bots visit the phishing URL, they hit a wall. Bots cannot click "I am human" or identify pictures of traffic lights. Because the bot sees nothing malicious on the CAPTCHA page, it marks the domain as "SAFE".

Only when a real human victim manually solves the puzzle does the actual attack begin.

3. AES-256 DOM Obfuscation

But the hackers don't stop there. Once the CAPTCHA is solved, the server doesn't send standard HTML code. If it did, network-level firewalls might still catch the words "Enter NetBanking Password."

Instead, the server sends a massively encrypted, obfuscated JavaScript payload. To any network scanner, it looks like harmless gibberish.

Initial Source Code (Firewall View) Encrypted 
<html>
  <body>
    <script>
      var _0x4b2a = "U2FsdGVkX1+QJk...[10k chars of Base64]...aZ9b=";
      var k = prompt("Verify Access"); // Secret from CAPTCHA
      
      // Decrypts payload only in the victim's browser
      document.write( CryptoJS.AES.decrypt(_0x4b2a, k).toString(CryptoJS.enc.Utf8) );
    </script>
  </body>
</html>

4. The Invisible Execution

The magic happens Client-Side. The victim's own browser takes the secret key provided by the CAPTCHA step, decrypts the massive Base64 string in real-time, and instantly writes the fake banking UI directly into the Document Object Model (DOM).

The phishing page renders perfectly on the screen, but if you "View Page Source," you will only see the encrypted script. Traditional antiviruses are entirely blind to this because they scan files and URLs, not the dynamically rendered memory of a web browser.
